A localhost lab walkthrough of three custom Nmap Scripting Engine checks for legacy NTP Mode 7 monlist behavior.

Author: Sanjith Madhavan  •  Lab: Ubuntu on WSL, Nmap 7.98, and Chrony

Topics: NTP / UDP 123 · Nmap Scripting Engine · Lua · CVE-2013-5211

Safety and interpretation: Run these checks only against systems you own or are authorized to assess. This walkthrough targets IPv4 loopback (127.0.0.1). A closed UDP/123 port, silence, or timeout is inconclusive, not proof that a host is secure. A normal NTP reply does not demonstrate monlist support.

This post complements my SNMP script article with the NTP half of the project. The scripts demonstrate how to structure limited NSE checks and report what the received packets actually show. They do not enumerate client addresses or prove vulnerability from silence.

Project files and the complete README are in my Nmap NSE audit scripts repository. The repository is public, so the scripts and lab notes are available without signing in.

1. What the three scripts check

  • ntp-custom.nse: reference-style check that sends one legacy monlist request. A reply must be validated before confirming exposure.
  • ntp-monlist-enhanced1.nse: validates expected Mode 7 response fields and distinguishes a non-matching reply from no reply. It reads one datagram and does not display client records.
  • ntp-monlist-enhanced2.nse: reports the first reply's size and a limited ratio to the request. It does not count additional packets or calculate a complete amplification factor.

A matching legacy reply would be a reason to review the server version and configuration. One packet alone does not establish whether CVE-2013-5211 applies.

2. Prepare the localhost lab

Clone the public project and install the tools:

git clone https://github.com/Sanjith-code/nmap-nse-audit-scripts.git
cd nmap-nse-audit-scripts
sudo apt update
sudo apt install -y nmap chrony
nmap --version

For this test, Chrony was configured to listen only on the loopback interface in /etc/chrony/chrony.conf:

allow 127.0.0.1
bindaddress 127.0.0.1

After restarting the service, ss showed Chrony listening on 127.0.0.1:123. Keep the service bound to loopback for this lab; do not expose it on a network interface.

3. Confirm Nmap can read the scripts

From the repository root, I checked the help text for all three scripts with Nmap 7.98:

sudo nmap --script-help ./scripts/ntp-custom.nse
sudo nmap --script-help ./scripts/ntp-monlist-enhanced1.nse
sudo nmap --script-help ./scripts/ntp-monlist-enhanced2.nse

Nmap displayed each script's description and categories. Its local-script-directory warning can be avoided for execution by setting NMAPDIR to the repository root, as shown below.

4. Run the three checks against localhost

With Chrony listening on the loopback address, I ran all three scripts against 127.0.0.1:

sudo env NMAPDIR="$PWD" nmap -sU -Pn -p 123 \
  --script ./scripts/ntp-custom.nse,./scripts/ntp-monlist-enhanced1.nse,./scripts/ntp-monlist-enhanced2.nse \
  127.0.0.1

The scan reported UDP/123 as open. All three scripts reported no monlist reply and marked the result inconclusive; the reference check said exposure was not demonstrated. This does not prove the host is secure or that every NTP implementation behaves the same way.

5. How to interpret the result

  • The open port confirms a local UDP service was present; it does not establish that the service supports legacy Mode 7 monlist.
  • No reply means the scripts could not demonstrate monlist exposure in this test. It is not proof of security.
  • A matching Mode 7 reply would warrant a review of the server version and configuration before making a vulnerability claim.
  • Enhancement 2 measures one datagram only; its ratio is not a full amplification measurement.

6. Conclusion

This localhost lab shows the reference NTP check and two bounded enhancements in action. The key lesson is to report only what the packet exchange demonstrates: in this run, UDP/123 was open, but the monlist exposure check was inconclusive. All testing described here is limited to systems I own or have explicit permission to assess.

The scripts and lab notes are available in the project repository (public).
