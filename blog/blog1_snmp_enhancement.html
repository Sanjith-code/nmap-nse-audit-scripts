In this post, I compare the original Nmap SNMP system-description script with two small enhancements I made for my cybersecurity lab.

Author: Sanjith Madhavan   |   Environment: Ubuntu / Nmap 7.98

This post documents my work with Nmap’s SNMP scripts. I started with the standard system-description script, then made two versions that explain the security meaning of a successful response more clearly.

The two changes are straightforward: the first reports a potential exposure when the default community returns a readable description; the second checks the device name as well and handles missing values more carefully. A missing reply is inconclusive, not proof that the service is secure.

1. Introduction to Nmap and NSE

I ran these commands against the local SNMP service in my Ubuntu environment. The outputs below show the reference script first, followed by the two enhanced versions.

SNMP (Simple Network Management Protocol) is commonly available over UDP port 161. A device that accepts a predictable community string such as public may expose management information. This article enhances a standard information-gathering workflow so that the output is more security-focused and easier to interpret.

2. Reference script — snmp-sysdescr.nse

The official Nmap snmp-sysdescr.nse script attempts to retrieve the device’s system description and uptime from standard SNMP objects. It is categorized as default, discovery, and safe. The upstream source is available at Nmap’s official script repository.

Reference source (.nse code only):

local datetime = require "datetime"
local nmap = require "nmap"
local shortport = require "shortport"
local snmp = require "snmp"
local string = require "string"

description = [[
Attempts to extract system information from an SNMP service.
]]

---
-- @usage
-- nmap -sU -p 161 --script snmp-sysdescr <target>
--
-- @output
-- |  snmp-sysdescr: HP ETHERNET MULTI-ENVIRONMENT,ROM A.25.80,JETDIRECT,JD117,EEPROM V.28.22,CIDATE 08/09/2006
-- |_   System uptime: 28 days, 17:18:59 (248153900 timeticks)
author = "Thomas Buchanan"

license = "Same as Nmap--See https://nmap.org/book/man-legal.html"

categories = {"default", "discovery", "safe"}

dependencies = {"snmp-brute"}

portrule = shortport.port_or_service(161, "snmp", "udp", {"open", "open|filtered"})

---
-- Sends SNMP packets to host and reads responses
action = function(host, port)

  local snmpHelper = snmp.Helper:new(host, port)
  snmpHelper:connect()
  -- build a SNMP v1 packet
  -- copied from packet capture of snmpget exchange
  -- get value: 1.3.6.1.2.1.1.1.0 (SNMPv2-MIB::sysDescr.0)
  local status, response = snmpHelper:get({reqId=28428}, "1.3.6.1.2.1.1.1.0")

  if not status then
    return
  end

  -- since we got something back, the port is definitely open
  nmap.set_port_state(host, port, "open")

  local result = response and response[1] and response[1][1]
  -- build a SNMP v1 packet
  -- copied from packet capture of snmpget exchange
  -- get value: 1.3.6.1.2.1.1.3.0 (SNMPv2-MIB::sysUpTime.0)
  status, response = snmpHelper:get({reqId=28428}, "1.3.6.1.2.1.1.3.0")

  if not status then
    return result
  end

  local uptime = response and response[1] and response[1][1]
  if not uptime then
    return
  end

  result = result .. "\n" .. string.format("  System uptime: %s (%s timeticks)", datetime.format_time(uptime, 100), tostring(uptime))
  return result
end

Reference script description

snmp-sysdescr.nse creates an SNMP helper, requests the sysDescr.0 object (OID 1.3.6.1.2.1.1.1.0), then requests sysUpTime.0 (OID 1.3.6.1.2.1.1.3.0). If the values are returned in the expected format, the script prints the device description and uptime. It is an information-gathering baseline; it does not explicitly classify the default community string as a security finding.

3. Enhancement options

OPTION 1

Clear security finding

Check sysDescr.0 using the explicit default community public; return a readable exposure message and mitigation when a value is received.

OPTION 2

More evidence, safer parsing

Query both sysName.0 and sysDescr.0, check each result before using it, and print whichever values are actually returned.

4. Enhanced script — option 1

This version adds an explicit public community check, validates the returned value before formatting the result, and includes a remediation message. It deliberately uses POTENTIAL EXPOSURE rather than claiming that every SNMP configuration is fully compromised.

snmp-public-check-option1.nse

-- snmp-public-check-option1.nse
-- Enhancement 1: clear finding, safe response parsing, and remediation guidance

description = [[
Checks whether an SNMP agent returns its system description when queried
with the default community string "public". A successful readable response
indicates potential information exposure. A missing response is inconclusive.
]]
author = "Sanjith Madhavan"
license = "Same as Nmap--See https://nmap.org/book/man-legal.html"
categories = {"discovery", "safe", "vuln"}

local shortport = require "shortport"
local snmp = require "snmp"
local nmap = require "nmap"

portrule = shortport.port_or_service(161, "snmp", "udp", {"open", "open|filtered"})

action = function(host, port)
  local helper = snmp.Helper:new(host, port, "public")
  helper:connect()

  local status, response = helper:get({reqId = 1}, "1.3.6.1.2.1.1.1.0")
  if not status then
    return "INCONCLUSIVE: No usable response to the sysDescr request using community 'public'."
  end

  local sysDescr = response and response[1] and response[1][1]
  if sysDescr == nil then
    return "INCONCLUSIVE: The SNMP request completed but no readable sysDescr value was returned."
  end

  nmap.set_port_state(host, port, "open")
  return "POTENTIAL EXPOSURE: SNMP returned sysDescr using the default community 'public'.\n"
    .. "  sysDescr: " .. tostring(sysDescr) .. "\n"
    .. "  Risk: Unauthorised system-information disclosure.\n"
    .. "  Recommendation: Remove default communities, restrict UDP/161, and prefer SNMPv3."
end

5. Enhanced script — option 2

The second version requests both sysName.0 and sysDescr.0. It checks that each value exists before printing it, so a missing field does not cause the script to crash.

snmp-public-check-option2.nse

-- snmp-public-check-option2.nse
-- Enhancement 2: query multiple standard objects and report validated evidence

description = [[
Checks whether the default SNMP community string "public" can read the
standard sysName.0 and sysDescr.0 objects. Reports only values returned by
the SNMP library and treats missing or unusable data as inconclusive.
]]
author = "Sanjith Madhavan"
license = "Same as Nmap--See https://nmap.org/book/man-legal.html"
categories = {"discovery", "safe", "vuln"}

local shortport = require "shortport"
local snmp = require "snmp"
local nmap = require "nmap"

local SYS_DESCR = "1.3.6.1.2.1.1.1.0"
local SYS_NAME  = "1.3.6.1.2.1.1.5.0"

portrule = shortport.port_or_service(161, "snmp", "udp", {"open", "open|filtered"})

action = function(host, port)
  local helper = snmp.Helper:new(host, port, "public")
  helper:connect()

  local status, response = helper:get({reqId = 2}, SYS_NAME, SYS_DESCR)
  if not status then
    return "INCONCLUSIVE: No usable SNMP response using the default community 'public'."
  end

  local sysName = response and response[1] and response[1][1]
  local sysDescr = response and response[2] and response[2][1]
  if sysName == nil and sysDescr == nil then
    return "INCONCLUSIVE: No readable sysName or sysDescr value was returned."
  end

  nmap.set_port_state(host, port, "open")
  local lines = {
    "POTENTIAL EXPOSURE: The default community 'public' returned readable system information."
  }
  if sysName ~= nil then
    table.insert(lines, "  sysName: " .. tostring(sysName))
  end
  if sysDescr ~= nil then
    table.insert(lines, "  sysDescr: " .. tostring(sysDescr))
  end
  table.insert(lines, "  Risk: Unauthorised system-information disclosure.")
  table.insert(lines, "  Recommendation: Disable default communities, restrict UDP/161, and use SNMPv3.")
  return table.concat(lines, "\n")
end

6. Running the scripts

Save the two code blocks using the filenames shown in the post. Then copy them into Nmap’s scripts folder and refresh the script database:

sudo cp snmp-public-check-option1.nse /usr/share/nmap/scripts/
sudo cp snmp-public-check-option2.nse /usr/share/nmap/scripts/
sudo nmap --script-updatedb

First check that Nmap recognises each script, then run it against your own lab machine:

sudo nmap --script-help snmp-public-check-option1
sudo nmap --script-help snmp-public-check-option2
sudo nmap -sU -p 161 --script=snmp-public-check-option1 127.0.0.1
sudo nmap -sU -p 161 --script=snmp-public-check-option2 127.0.0.1
Interpret results carefully: A readable response to a request that explicitly uses public is evidence that the community is accepted for that request. A timeout or missing value is inconclusive; it can result from filtering, service settings, protocol errors, or lack of response. Do not label a target “secure” based on silence alone.

7. What I learned

  • Understood the purpose and structure of Nmap NSE scripts: metadata, libraries, portrule, and action.
  • Read the official snmp-sysdescr.nse source and identified its use of sysDescr.0 and sysUpTime.0.
  • Enhanced the output with security-focused context and remediation guidance.
  • Added response-table validation to avoid a nil-index error when a value is missing.
  • Learned to distinguish a confirmed response from an inconclusive timeout.

8. Conclusion

The reference script is useful for seeing what information an SNMP service returns. Option 1 makes the potential exposure easier to notice and adds a recommendation. Option 2 checks the device name and description, with extra checks for missing response values. The results still need to be interpreted carefully: a missing response does not prove that the service is secure.

All scans should be performed only on systems you own or have permission to assess.
